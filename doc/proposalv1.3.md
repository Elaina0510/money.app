## 需求清单

### 1. 记账页 — 返回时未保存提醒

**优先级：** 高

**现状：** 用户在记账页（RecordFormPage）填入内容后，点击返回直接退出，无任何提示，已填写的数据丢失。

**目标：** 一旦用户修改过任何字段（金额、分类、备注、日期等），点击返回时弹出确认对话框，提示"你确定要放弃更改吗？"。

**验收标准：**
- 用户未做任何修改时，返回行为不变（直接退出）
- 用户修改了任意字段后，返回时弹出确认弹窗
- 弹窗包含"取消"和"确定放弃"两个选项
- 点击"取消"留在当前页，点击"确定放弃"退出并丢弃更改
- 需兼容浏览器物理返回键（popstate / beforeRouteLeave）

**涉及文件：** `frontend/src/pages/RecordFormPage.vue`

---

### 2. 日历组件 — 风格升级与动画

**优先级：** 中

**现状：** 记账页和账单页筛选框中使用的日历弹出样式过于简陋，与整体设计风格不统一。

**目标：**
- 日历组件视觉风格与整体 Material Design 保持一致
- 日历打开时，从点击位置以 expand 动画展开至画面中心
- 动画流畅自然，建议使用 Vuetify 的 transition 或 CSS transform/clip-path 实现

**验收标准：**
- 日历在记账页（RecordFormPage）和账单页筛选框（RecordListPage）中均呈现新风格
- 点击触发点 → 日历从该位置扩大的动画 → 最终居中显示
- 动画时长适中（建议 200-300ms），不卡顿

**涉及文件：**
- `frontend/src/pages/RecordFormPage.vue`
- `frontend/src/pages/RecordListPage.vue`

---

### 3. 账单页 — 详情展开动画

**优先级：** 中

**现状：** 点击账单条目后跳转到详情页，切换生硬。

**目标：** 点击账单栏后，从该条目位置以 expand 动画逐渐扩大至完整画面，与日历动画风格保持一致。

**验收标准：**
- 动画起始位置为被点击的账单条目
- 动画展开至完整的详情页画面
- 动画风格与需求 #2（日历动画）保持一致的 expand 效果
- 建议使用 Vue Router 的过渡动画（`<Transition>` + 路由 meta）或 Vuetify 的 `v-dialog` / `v-expand-x` 实现

**涉及文件：**
- `frontend/src/pages/RecordListPage.vue`
- `frontend/src/pages/RecordDetailPage.vue`
- `frontend/src/router/index.ts`（路由过渡配置）

---

### 4. 账单页 — 分类图标替代收支图标

**优先级：** 低

**现状：** 账单列表中每条记录前端显示的图标代表"收入"或"支出"（统一的收入/支出图标）。

**目标：** 删除统一的收入/支出图标，改为显示该记录所属分类的图标。

**验收标准：**
- 账单列表每条记录前端显示的是该记录分类对应的图标
- 分类图标来自用户设置的分类数据（需确认图标数据源）
- 收入/支出的区分不再依赖图标，可通过其他视觉元素（如颜色、标签）体现

**涉及文件：**
- `frontend/src/pages/RecordListPage.vue`

---

### 5. 全局 — 页面滑动模糊渐变

**优先级：** 中

**现状：** 页面滚动时，内容区域边缘直接截断，没有过渡效果。

**目标：** 垂直滑动时，在以下两个位置添加模糊渐变效果：
- **顶部标题下方**：固定标题栏下方出现模糊过渡，内容滑入时渐隐
- **底部边缘**：页面底部出现模糊渐变，提示下方还有内容

**验收标准：**
- 向下滚动时，固定标题（主页、设置等）保持置顶不动，标题下方出现模糊渐变遮罩
- 页面底部边缘出现模糊渐变效果
- 模糊效果使用 CSS `mask-image` 或 `backdrop-filter` 实现
- 移动端和桌面端均生效
- 模糊效果不影响页面的正常滚动和点击交互

**涉及文件：**
- `frontend/src/components/layout/AppLayout.vue`（标题栏模糊）
- `frontend/src/styles/global.scss`（全局样式）
- 各页面的滚动容器

---

### 6. 宽屏适配 — 桌面端整体放大 110%

**优先级：** 低

**现状：** 桌面端（≥960px）内容区最大宽度为 640px，在大屏幕上内容显得偏小。

**目标：** 在桌面端（≥960px）使用 CSS `transform: scale(1.1)` 对整体内容进行放大，视觉上等效于 704px。

**方案：**
```css
@media (min-width: 960px) {
  .content-wrapper {
    transform: scale(1.1);
    transform-origin: top center;
  }
}
```

**验收标准：**
- 移动端（<960px）不受影响，保持 100% 原始比例
- 桌面端（≥960px）所有内容（文字、间距、图标）统一放大 110%
- 放大后不出现水平滚动条
- 放大后不影响页面的交互功能（点击、滚动等）
- 侧边栏和底部导航栏的布局不受影响

**涉及文件：**
- `frontend/src/components/layout/AppLayout.vue`
- `frontend/src/styles/global.scss`
